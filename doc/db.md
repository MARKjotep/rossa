# Database adapters

Rossa's database layer provides typed schemas and a repository API over Bun's
SQL client. SQLite works without an additional driver dependency.

## SQLite setup

`createSqliteDatabase()` opens Bun SQL on a SQLite file, creates missing parent
directories, and applies safe defaults (WAL journal, `NORMAL` durability,
foreign keys on, 5 s busy timeout):

```ts
import { createSqliteDatabase } from "@/db";

const { db, info, close } = await createSqliteDatabase("data/app.db");
console.log(info.journalMode); // "wal"
// ...use db with DbRepository or raw Bun SQL...
await close();
```

For a connection you already own, `configureSqlite(db)` applies the same
PRAGMAs and returns the effective settings. `NORMAL` synchronous is safe with
WAL but can lose the last commits on power loss; choose `{ synchronous: "FULL" }`
when that tradeoff is unacceptable. `sqliteWalCheckpoint(db)` flushes the WAL
back into the main file, and `sqliteIntegrityCheck(db)` reports corruption
details.

`DbRepository<T>` contains shared CRUD and transaction behavior. A
`DbDialectAdapter` supplies database-specific column types, DDL, upsert,
inspection, truncation, and optimization. See the
[dialect guide](../src/db/dialects/README.md) for the steps to add a backend.

```ts
import type { SQL } from "bun";
import { DbRepository, DbSchema, sqliteDialect, t } from "@/db";

interface UserRow {
  id: number;
  name: string;
}

const schema = new DbSchema<UserRow>(
  "users",
  {
    id: t.serial().primary,
    name: t.text().notNull,
  },
  sqliteDialect,
);

declare const db: SQL; // Bun SQL connection configured for SQLite
const users = new DbRepository<UserRow>(db, schema);
await users.create();
```

## CRUD and queries

Use the repository for typed, parameterized CRUD operations:

```ts
const created = await users.insert({ id: 0, name: "Rosa" });
const rosa = await users.find({ name: "Rosa" });
const matching = await users.findAll({
  name: { operator: "LIKE", value: "R%" },
});
const page = await users.paginate(1, 20, { name: "Rosa" });
const updated = await users.update({ id: 1 }, { name: "Rosa M." });
const removed = await users.delete({ id: 1 });
```

`findAll()`, `count()`, and `exists()` accept the same typed conditions.
Conditions combine with `AND`; operators include comparisons, `LIKE`, `IN`,
and `IS`. Values are bound as parameters. Keep table and column names in
trusted schema definitions.

`findMany()` adds ordered, limited reads without raw SQL:

```ts
import type { FindManyOptions } from "@/db";

const latest = await users.findMany({
  where: { name: "Rosa" },
  orderBy: { column: "id", direction: "desc" },
  limit: 50,
});
```

`where` accepts the same conditions as `findAll`. `orderBy.column` must be a
schema column and the direction is `"asc"` (default) or `"desc"`; both are
validated against the schema, and `limit` must be a positive safe integer. The
`FindManyOptions<T>` type is exported.

## Indexes and auto-increment

`DbSchema` takes an optional fourth `{ indices }` argument. Indexes are emitted
idempotently by `createSQL()` and applied by `create()` for every dialect:

```ts
interface MessageRow {
  id: number;
  topic: string;
  body: string;
}

const messages = new DbSchema<MessageRow>(
  "messages",
  {
    id: t.serial().primary.autoIncrement(),
    topic: t.text().notNull,
    body: t.text().notNull,
  },
  sqliteDialect,
  {
    indices: [
      { name: "messages_topic_id", columns: ["topic", "id"] },
      { name: "messages_body", columns: ["body"], unique: true },
    ],
  },
);
```

Index names must be unique per schema, every column must exist in the
definition, and `unique` is optional. `schema.indices` returns the validated
list; `createTableSQL()`, `createIndexSQLs()`, and `createStatements()` expose
the generated DDL.

`Column.autoIncrement()` (flag `isAutoIncrement`) is available on `serial()`,
`int()`, and `bigint()` columns. SQLite renders `PRIMARY KEY AUTOINCREMENT`
and rejects the flag on a non-primary-key column; PostgreSQL renders
`GENERATED BY DEFAULT AS IDENTITY` and MySQL `AUTO_INCREMENT` on non-serial
columns (`serial()` is already generated in both). Calling it on another column
type throws.

`DbDialectAdapter` gained two index members for this feature: `createIndexSQL`
and `createIndex`. Custom adapters must implement both; adapters written for
0.1.4 and earlier no longer satisfy the interface.

## Schema changes

`create()` creates the table if needed. `syncColumns()` adds missing columns
and keeps existing ones by default. Pass `true` only when dropping columns is
intentional, since that can destroy data:

```ts
await users.syncColumns();
// await users.syncColumns(true); // Also drop columns missing from the schema.
```

Create an equivalent schema with `postgresDialect`, `mysqlDialect`, or
`mariadbDialect` for PostgreSQL, MySQL, or MariaDB. `getDialect("mysql")` and
`getDialect("mariadb")` are also available. Bun's `mysql2://` URL is compatible
with `mysqlDialect`. The schema uses logical types (`t.int()`, `t.json()`,
`t.timestamp()`, and others); the selected adapter maps them to the database's
native column types. See the [dialect guide](../src/db/dialects/README.md) for MySQL
write behavior and current limitations.
